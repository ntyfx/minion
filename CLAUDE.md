## Commands

This project uses **pnpm** as the package manager.

```bash
# Development
pnpm dev              # Start Next.js dev server on http://localhost:3000

# Building
pnpm build            # Production build (static export to out/)

# Linting
pnpm lint             # Run ESLint

# Testing
pnpm test             # Run Vitest unit tests in watch mode
pnpm test run         # Run Vitest unit tests once
pnpm test:coverage    # Run unit tests with coverage
pnpm test:e2e         # Run Playwright E2E tests
```

## Architecture

### Tech Stack

- **Framework**: Next.js 16 with App Router (static export)
- **UI**: Ant Design 6 + Ant Design X, Tailwind CSS v4
- **Language**: TypeScript (strict mode)
- **State**: React hooks + Context for theme/locale
- **Storage**: IndexedDB via `idb` library for sessions
- **Testing**: Vitest + React Testing Library (unit), Playwright (E2E)

### Key Architectural Patterns

**Static Export with GitHub Pages**: The app is configured for static export (`output: 'export'`) and deployed to GitHub Pages. In production, `basePath` and `assetPrefix` are set to `/minion`. The dev server runs without a basePath.

**SSE Streaming**: The chat interface communicates with the backend via Server-Sent Events. The `streamChat()` function in `src/lib/sse-client.ts` handles the stream parsing, including content chunks, reasoning details, token usage, and error events.

**Multi-Theme System**: 6 themes (light, dark, premium-dark, latte, dusk, dawn) defined in `src/lib/themes.ts`. Themes use CSS custom properties defined in `src/app/styles/themes.css`. The theme is applied via a script in the HTML head to prevent flash, then managed by `ThemeProvider` context.

**Internationalization**: Uses `next-intl` with a hardcoded default locale (zh-CN). Locale files are in `src/locales/`. The `useTranslations` hook from next-intl is used throughout components.

**Session Persistence**: Chat sessions are stored in IndexedDB via `src/lib/session-db.ts`. The `useChatSessions` hook manages session CRUD operations with optimistic UI updates.

**Service Worker**: Registered only in production (disabled on localhost to avoid caching issues during development). The SW is generated by Next.js for offline support.

### Project Structure

```
src/
├── app/                 # Next.js App Router
│   ├── styles/          # Modular CSS files (themes.css, chat.css, etc.)
│   ├── layout.tsx       # Root layout with theme bootstrap script
│   └── globals.css      # Main CSS imports
├── components/          # React components
├── hooks/               # Custom React hooks
├── lib/                 # Utilities, DB helpers, SSE client
├── types/               # TypeScript interfaces
└── locales/             # i18n JSON files
```

### Testing Setup

- **Unit tests**: Colocated with source files (e.g., `lib/__tests__/sse-client.test.ts`)
- **Vitest config**: `vitest.config.ts` with jsdom environment, `@/` path alias
- **Test setup**: `vitest.setup.ts` mocks `next-intl`, `matchMedia`, and browser APIs (ResizeObserver, IntersectionObserver)
- **E2E tests**: Located in `e2e/` directory, uses Playwright with Chromium

### CI/CD Pipeline

GitHub Actions workflow (`.github/workflows/deploy.yml`):
1. **check**: Install deps, run lint, type check (`tsc --noEmit`), audit
2. **build**: Build static export, upload artifact
3. **deploy**: Deploy to GitHub Pages

### Important Configuration

- **next.config.ts**: Static export config with basePath handling for production
- **tsconfig.json**: Path alias `@/*` maps to `./src/*`
- **vitest.config.ts**: Tests only files matching `src/**/*.test.{ts,tsx}`
- **playwright.config.ts**: E2E tests against `http://localhost:3000`, reuses existing dev server if available

## Release Workflow

Follow these steps to create a new release:

```bash
# 1. Create a feature branch from main
git checkout -b feature/your-feature-name

# 2. Make changes, add/update tests
echo "完善测试用例..."

# 3. Run lint
pnpm lint

# 4. Push branch and create PR
git push -u origin feature/your-feature-name
gh pr create --title "feat: your feature description" --body "PR description"

# 5. Merge PR via GitHub (gh pr merge or web interface)
gh pr merge

# 6. After merge, switch to main and bump version
git checkout main
git pull
npm version patch  # or minor/major - updates package.json and creates git tag

# 7. Push tag to trigger release (GitHub Actions deploys on push to main)
git push --follow-tags

# Create GitHub release from tag
gh release create v$(node -p "require('./package.json').version") \
  --title "Release v$(node -p "require('./package.json').version")" \
  --generate-notes
```

**Version bumping**: Use `npm version patch|minor|major` which:
- Updates version in package.json
- Creates a git commit (e.g., "1.14.1")
- Creates a git tag (e.g., "v1.14.1")

**Auto-deployment**: Pushing to `main` triggers the deploy workflow. The prebuild script (`scripts/write-version.mjs`) writes the version to a file for the app to display.
